# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed

- Antigravity agents show their context and model: a supervised agy agent or coordinator now records its conversation id, read from the `presence/<id>.lock` its process holds open (transcript adapters may implement `live_session`), so its transcript is read and a restart resumes it. The preset's busy marker is `esc to cancel`, so a long thinking turn is no longer taken for a stall and nudged.
- A profile's own `busy_pattern` and `sessions_dir` now take precedence over the project-wide `[instances]` values, which apply only to a profile that sets none; a Claude-specific `[instances] busy_pattern` no longer makes every other CLI look idle.
- An agent whose transcript is being written counts as active even when it changes no file, so a slow model is not nudged as stalled.
- The context meter follows the model of the newest answer for workers and the coordinator, and takes the window from the CLI's own setting when the adapter reports one (OpenCode's configured `limit.context`), else `[models] context`; otherwise the window is unknown and the console shows the tokens in use and `n/a`, never a guess (popups name the source). The profile key `context_limit` is ignored, with a `config check` warning. The coordinator meter used the default profile's limit, and its model came only from the profile. `gemini-*` defaults to 1,048,576.
- Commands that report failure through their return status now exit with it (`theseus agents up|restart|scale|...` exited 0 on failure).
- Worker-log archiving in `merge`, `tasks retire` and `cleanup` copies symlinks as links (build trees leave dangling `/proc` links) and skips unreadable files with a warning; after a merge commit, an archive problem is a warning that says the merge succeeded.
- The changed-files manifest accepts a deletion written either way round (`DELETED  path` or `path  DELETED`), and the worker skill's manifest command records deletions.
- Repeated list options (`tasks add|edit --accept A --accept B`, `--owned`, `--touches`, `--depends`) keep every value instead of the last.
- Attention shows an open question's text and `tasks show` lists the task's open questions.
- A gateway pause or cap cut needs a project's coordinator only while it holds work back there (an agent of that pool holds a task, or a task waits for assignment); its age is the pool's latest error and it names the agents whose errors caused it.
- Room `dirty_paths` written as a file-name prefix (`docs/investigations/re-`) mean the same glob (`re-*`) in the sparse checkout, the task message and the ownership rule.
- `tasks complete --from-log` refuses a verify log of a commit that does not contain the task's merge, and names `--check/--log` for non-verify evidence; `theseus verify` prints the commit it verifies.
- Manual `dispatch` is stopped only by the candidate's own or project-wide rule problems, not by an unrelated record's. A completed task without an owner is valid when no worker ever ran it (an administrative completion).
- `docs fold-apply` refuses to move a report an open task still owns, which the next `tasks export` would write back.
- A session reached by switching inside the private tmux server (prefix `C`, `n`, `p`, or an attach from inside it) follows the terminal's size instead of staying pinned at the agent size by an earlier detach.
- Leaving an agent opened in place from the console (C-q) no longer leaves tmux's `[detached (from session X)]` line on the terminal, where the lines piled up and showed when the console quit.

### Changed

- The console's command palette (Ctrl+P) is grouped: opened empty it lists the highlighted row's actions, the tab's own few and one entry per group (Agent actions, Task actions, Scale agents, Pool slots, Handoffs, Profile actions, New profile) that opens the group in its own list; typing still searches every action. On a project with 68 actions the empty palette lists 10. WAITING is now QUEUE, and its `min cap` column `cap`.
- Console agents table: `CPU` and `RAM` (resident size only; the popup keeps the share of system RAM) follow `pool`, the session column is gone (popups show it), and a capability or task minimum (its difficulty) shows as three dots of two levels each (◐○○ 1, ●○○ 2, ●◐○ 3, ... ●●● 6), also before the task each agent works on. Every task has a difficulty: one without a minimum counts as the lowest level, 1 (shown in the waiting table, the agents table and the task popup as the default). A 1,048,576-token window reads `1M`.

### Added

- The coordinating skill asks coordinators to log theseus bugs, friction, stale instructions and improvement ideas in `.theseus/friction.md` of the main checkout as they happen, in a fixed entry format (`references/friction.md`), including the theseus problems workers report in their handoffs.
- `theseus profiles [list|show NAME|add NAME --preset P ...|edit [NAME]|remove NAME]` manages agent profiles in the host config (or `theseus.local.toml` with `--project`), inside a project or not: `show` prints every resolved key with its source, `add` and `remove` keep a file only when it validates, `edit` opens `$VISUAL`/`$EDITOR` at the profile's section and offers to edit again or revert while the saved file does not validate. The console's Host tab lists the profiles (PROFILES): Enter shows one, `E` edits it, Ctrl+P creates one from a preset or opens the host config.
- `theseus close [--reason TEXT] [--commit] [--force]` closes a project in one step: writes the task export (optionally committed), stops its supervised agents, queue driver and coordinator, keeps them stopped (`agents up` and `coordinator up` refuse it; `agents up --all-projects` and the console skip it), and names what is left to commit or push. `theseus reopen` brings back the agents that ran under their own names, the queue driver and the coordinator. `theseus projects --all` lists closed projects with their reason. Nothing is deleted. In the console a closed project is a dim PROJECTS row; Enter opens a read-only tab (CLOSED banner, tasks, waiting table, events, handoffs, read once), whose Ctrl+P offers only Reopen project, while an active project's Ctrl+P offers Close project; closed projects stay out of host-wide events and charts.
- `tasks add --hold` creates a task held in the same transaction; `tasks edit --append-note TEXT` adds a dated line to the coordinator note (both also in the MCP tools).
- `theseus doctor` warns when `commands.build`, `smoke` or `verify` is empty.

- Antigravity CLI (`agy`) support: new `antigravity` preset (alias `agy`) for headless (`agy -p ... --output-format json --mode auto`), worktree `--continue` follow-ups and interactive tmux launches (`agy --mode auto`, `/compact`, `/clear`, `/exit`, `--conversation` resume); new `antigravity-jsonl` transcript adapter reading `<sessions_dir>/<conversation-id>/.system_generated/logs/transcript.jsonl`; `theseus setup skill --client antigravity` and `[re] clients` skill resolution for `~/.gemini/config/skills`; `gemini-*` 1M context window default; and supervised agent/coordinator handling for profiles with `session = "none"` so they start fresh without preassigning or resuming a fabricated session id. See [Antigravity](docs/configuration.md#antigravity).
- Coordinator session: `theseus coordinator up|down|restart [--fresh]|attach [--read-only]|status` runs the project's coordinator as the supervised session `PROJECT--coordinator` on the private tmux server, in the project root, from `[coordinator] profile` (project, or the host's `[defaults] coordinator.profile`; no built-in default, a missing one is an error naming the key). It runs with the coordinator's own MCP config (`theseus mcp --role coordinator`) and never a worker's credentials or `THESEUS_AGENT*` variables; each run is an `agent_runs` row under the reserved name `coordinator` and a `coordinator_sessions` row (no schema change). The pane-died hook, and the queue driver after each tick, restart a crashed or lost coordinator with the `[supervisor.restart]` backoff, resuming its conversation. Every start registers it for the attention push; a new conversation gets one start prompt from the project-owned template `.agents/skills/theseus-coordinating/session-prompt.md` (`[coordinator] prompt`). `attach` nests correctly inside your own tmux (TMUX unset) and switches the client inside the private server. `[coordinator] autostart = true` makes `theseus agents up` bring it up. The console lists it first in AGENTS with the role coordinator, and `A` attaches to it. The names `coordinator` and `queue` are reserved for agents.
- Private tmux server configuration, generated by theseus and applied to that server only (never to your own server, never sourcing `~/.tmux.conf`): tmux-256color with true color, OSC 8 hyperlinks, extended keys, `escape-time` 0, focus events, `set-clipboard`, windows and panes from 1, `window-size latest`, the mouse wheel entering copy mode, vi copy mode with `v` and `y`. `[tmux] prefix` (host, `C-b`) so it can nest under a `C-a` tmux; prefix `a` (attention popup), `T` (console popup), `C` (coordinator), `n`/`p` (the project's sessions), `w` (choose-tree by project), `d` (detach), `r` (reload). Each project has a stable color (`[project] color`, a palette name or `#rrggbb`, else derived from the name) for its sessions' status bar and active border and the console's accents. The status bar shows project, role and task on the left and the attention count (red when nonzero), working/max, gateway state and the time on the right, from a small cache the queue driver writes after each tick (`theseus tmux status`). `theseus tmux apply` re-applies it to a running server without resizing or respawning agents (also done automatically when an older theseus started the server); `[tmux] extra_conf` sources a personal file last.
- Typing into a pane left in copy mode (a mouse wheel scroll) first leaves copy mode, since tmux would take the keys as copy-mode commands.
- The `opencode` preset is verified with OpenCode 2.3.0 as a supervised agent: `opencode --standalone` per agent, preassigned `ses_` session ids resumed with `--session`, busy (`esc interrupt`), its permission prompt and question dialog as waiting, `/compact`, `/clear`, `/exit`, the input box and context hint, and gateway errors after OpenCode's own retries. The new `opencode-sqlite` transcript adapter reads OpenCode's session database for the context meter, gateway error classification and the Conversation tab. New profile keys: `session_prefix`, `model_env` (the model through the environment, since the TUI has no model flag), and `mcp_format` with `mcp_env` (an MCP config in OpenCode's format named by `OPENCODE_CONFIG`, which also disables the servers of the user's global OpenCode configuration that `mcp_servers` leaves out). The preset turns OpenCode's self-update off for its agents. The supervised coordinator gets the profile's session prefix and MCP environment too. A wrapped input line now counts as holding the text when its last row is part of it. See [OpenCode](docs/configuration.md#opencode).
- Attention list: `theseus attention [--json]` lists what needs the coordinator now (deliveries waiting to merge, merges not yet verified, open worker questions, agents stalled, at a prompt, at a startup dialog, failed or gone, gateway pauses and cap cuts, assignments failing past their backoff, a stopped queue driver, a task export edited by hand or missing a completed task, verification debt past the pre-push guard's limits), each with a stable key, kind, project, since time and suggested command. It is computed from the store and live state on every call, so an item disappears only when its cause is resolved; `--follow` prints one line per change and never exits. The console shows a stopped driver and, past `[attention] escalate_minutes` (60), a red ESCALATED line.
- Push into the coordinator, opt-in: `theseus coordinator register [PANE]` records the coordinator's tmux pane (`$TMUX_PANE` by default) and its pid; with `[attention] notify = "pane"` the queue driver types one line into it after a tick whenever items were added (`theseus: 3 items need you (2 deliveries, 1 stalled agent); run theseus attention`), through the verified send, never into a prompt or over typed input, never twice for an unchanged list, and one reminder after `remind_minutes` (30). An item open past `escalate_minutes`, or the registered pane gone or stuck, runs the host's `[attention] escalate_command` once with the summary on stdin (off by default). Push bookkeeping lives in `<data>/queue/attention.json`; no schema change.
- Supervised queue driver: `theseus agents up` starts the project's `queue run` as the session `PROJECT--queue` on the private tmux server (also for a project with only hand-made panes), the pane-died hook restarts it with the `[supervisor.restart]` backoff, and `theseus agents down --all` stops it. `agents up` starts none while a live `queue run` already drives the project; `[queue] driver = false` opts out. The coordinating skill now runs `theseus attention` every turn and relies on push or `--follow`; `queue wait --no-drive` keeps working.
- Task store: live task state moves from `docs/project/tasks.json` into the host store (schema version 7: project ids and task, attempt, note, event and credential tables; a `-pre-v7` backup is taken first). `theseus tasks import` loads a project's files once, checked lossless (the store is backed up first); `theseus tasks export` writes `tasks.json`, `tasks-archive.jsonl` and the new `tasks-history.jsonl` for the coordinator to commit; `tasks edit` changes a pending task (an in-progress one with `--force`), including `--external-blocker`/`--research-required` with `--unblock`; `tasks adopt` records a moved checkout; `db prune --with-tasks` exports a project's tasks before removing it. Until a project is imported its task commands say to run `tasks import`; a new project imports itself on first use.
- Worker task commands: `theseus task show|note|done|blocked TASK` (the worker names its task; a stale context gets `not-your-task`). `task note --question` wakes `theseus queue wait` until the coordinator answers with `tasks note`; `queue status` lists open questions. Supervised agents and dispatch workers get a 0600 credentials file (`THESEUS_CREDENTIALS`) whose run secret authenticates only while the run or attempt lives; commands that change task state require the coordinator and refuse an agent, a hand-made agent's pane or a task worktree. `tasks` and `task` subcommands take `--json`.
- `theseus mcp`: the task tools as an MCP server over stdio (optional extra `theseus-lab[mcp]`). Worker tools (`task_show`, `task_note`, `task_done`, `task_blocked`) from `THESEUS_CREDENTIALS`; the coordinator's reads plus add, edit, hold, release, reopen and note with `--role coordinator` in its own config. A profile listing `theseus` in `mcp_servers` gets a per-agent MCP config naming that agent's credentials.
- Sandboxed workers: each in-progress task has a copy with its rendered prompt in `.theseus/task.json` (rewritten on every change), which `task show` reads when the store is out of reach; `task note|done|blocked` then leave their report in `.theseus/outbox/`, which the next tick takes in.
- Task export bookkeeping: a passing `theseus verify` and `tasks complete` write the task export; `theseus doctor`, `theseus upgrade` and the console's PROJECT panel say whether the committed export is current, stale or hand-edited (a hand edit is ignored). `theseus upgrade --import-tasks` imports a project. The queue backs the store up hourly while tasks change; `[store.backups] offsite` (optional) receives the daily and weekly copies; `theseus doctor` warns about a store on a network filesystem. `theseus db downgrade 6` removes the task store for an older theseus once every export is current. Detected deliveries say so in the event feed.
- Soft ownership: `tasks add --touches FILE` (and `tasks edit --touches`) names shared files a task will patch. A pending task waits while a running or delivered task owns overlapping paths or owns or touches a file it touches, including the patch targets each tick reads from running worktrees and each delivery reports; `tasks list`, `queue status` and the console show `touches FILE (TASK)`.
- Profile fallback, host-wide: `[workers.<name>] fallback = "<profile>"` with an optional `[workers.<name>.health]` probe command (exit 0 means healthy; `probe_seconds` 600, `recover_after` 3, `probe_timeout` 60; passive health with `down_errors` 2 and `down_window_minutes` 10 when no probe is set). Model health is host state in the store: model-level errors (5xx, connection lost) confirmed by a failed probe mark a profile down, a 429 never does. While it is down, every project's supervisor moves its `[agents.counts]` onto the fallback (counts kept: idle agents switch at once, working ones finish first, one stuck on a gateway error has its task released with the worktree kept and the next attempt pointed at it); tasks pinned to the profile and its capacity follow. After `recover_after` consecutive OK probes the agents drain back. Each switch is a `fallback` event that wakes `theseus queue wait` once, and the console and `theseus pool` show the profile on fallback and why.
- Key-level 429s (`Rate limit exceeded for api_key`, the parallel cap, an account's per-minute rate limit) pause the pool host-wide for the first backoff, cut its working cap and hold the newest working agents beyond the cap (nothing typed into them: no resend, reminder or restart prompt; `turn_held` and `turn_resumed` events). They no longer count toward the circuit breaker.
- Optional token budget per pool: `[pools.<name>] tokens_per_minute` (no default) and `turns_per_minute` (6). Each working agent is estimated at its context size times `turns_per_minute`; the newest beyond the budget are held and no new task starts until the estimate fits.

- Agent IDs: each registered agent gets a ULID, and events, deliveries, samples, pool leases, gateway errors and retries, supervisor runs and task records (`ownerId`, `agentId` on `previousAttempts`) are keyed by it, so a reused name never inherits an earlier agent's history, crash budget, retry episode or open task. Names stay what users see and type; `agents ls --json`, `top --json` and `tasks show` include the ID. Host store schema version 6 (additive) backfills one ID per existing agent and maps existing records to it by name; `theseus tasks migrate-ids` fills older task records (idempotent), and older theseus versions ignore the new task fields.
- Agent popup Conversation tab (`c`): the agent's conversation from its session record, natively scrollable, with user and assistant messages, each tool call and result folded to one line that a click or Enter expands, thinking left out; it follows new entries unless you scrolled up and is read incrementally in a worker. It comes from a transcript adapter chosen by the profile's new `interactive.transcript` key (`theseus.adapters`; `claude-code-jsonl` for the Claude Code presets). Profiles without an adapter show the pane's tmux scrollback (`pane-history`, the codex, opencode and gemini-cli presets) or no tab (`none`). Everything shown is redacted like gateway excerpts.
- The mouse wheel over the pane mirror or the conversation scrolls only that view, never the popup or the screen behind it, also at its ends.
- The console's pane mirror sizes a supervised agent's window on the private server to what the mirror shows while its popup is open (following a console resize after about 200 ms and fitting again after an attach), so the agent redraws without sideways scrolling; closing the popup, or quitting the console with it open, restores `[supervisor] size`. Hand-made panes on your own tmux server are never resized.
- The test suite is cut from 334 tests and about 400 s to a small core that runs in about 30 s with `python -m unittest discover -s tests`.
- Capability gating: a profile carries an integer `capability` (host config, default 1) and a task a minimum (`theseus tasks add --min-capability N`, `theseus tasks capability ID N`, console actions). The queue assigns a task only to agents whose profile meets it; an agent registered with exactly the task's profile always qualifies, and a relaunch onto a compatible task profile must meet it with both profiles. The console's WAITING reason says `needs capability >= N`.
- One restart prompt per fresh context: an agent restarted fresh with a task (`theseus agents restart NAME --fresh --with-task [--file PROMPT]`, a supervised fresh start, a gateway or idle-stop recovery that clears the context) is owed one task-aware prompt (task and record summary, worktree, task prompt, partial report and `notes.md`, how to resume in small steps). Until it is confirmed received nothing else is typed into the agent and a scheduled gateway resend is called off; unconfirmed tries end in a `stalled` event. Workers keep progress notes in `.theseus/notes.md`.
- `queue.send_budget_seconds` (25): a tick types all its messages, presses Enter after one shared pause and verifies them together in a bounded thread pool within this budget; a send still unresolved is finished by the next tick.
- Retention for every growing host store table: `[store.retention]` `deliveries_days` (365), `runs_days` (90, an agent's latest run is kept) and `gateway_days` (7, gateway errors and settled retry episodes); `events_days` now defaults to 365.
- Context use is measured against the window of the model the session transcript names (`[models] context`, prefix keys with `*`); current Claude models default to 1M. Unknown models fall back to the profile's `context_limit`.
- Control console: `theseus` alone on a terminal opens it (`theseus console`, `theseus top` stays an alias; `--once` and `--json` for scripts). A PROJECT panel per project tab in aligned labeled columns (milestone, branch, verification, queue state; the coordinator with state, last activity and context; the queue watcher from a heartbeat `queue wait`/`run` now write; queue, review age and attention; agents by state, pool slots with a cap cut, gateway; today's merges), and a PROJECTS table on the Host tab with the same figures per project (replacing the project cards). The coordinator opens with `C` or a double-click (mirror and send line). Supervised agents show short names, uptime, restarts, session, model and pool; their popup lists labeled fields and has Live, Diff, Task and Events tabs, attaches in place with Enter (C-q detaches), opens a tmux window with `o`, and restarts, stops or starts with `R`, `X`, `U` after a confirmation. Ctrl+P lists the project's actions (queue tick, agents up, add or remove an agent, restart, stop, start, attach, dispatch, hold, release, priority, reopen, pool hold and release, coordinator, handoffs), each running the theseus command of the same name.
- `theseus agents scale PROFILE COUNT` writes `[agents.counts]` in `theseus.local.toml` and reconciles.
- `[agents.counts]` counts live agents: down or disabled agents do not count, scaling down stops free agents first and then the most recently started (never by slot number), and scaling up starts the lowest name never used or removed; a downed agent stays down under its name. `theseus agents down NAME --replace` starts its replacement at once. `theseus agents down --all` (and the console's Stop all agents) pauses supervision for the project, kept in the host store and shown as `paused` in `agents ls` and the project panel, until `theseus agents up`.
- Host-wide console views (EVENTS, GATEWAY and POOLS on the Host tab) show agents as `project/short`, since short names repeat across projects.
- `theseus queue wait` and `queue run` outlive a store upgrade: on a newer schema they become the installed theseus with the same arguments when it knows the schema (`theseus --schema-version`), else print one line and retry each interval. They also restart themselves with the same arguments when the theseus code on disk changes (checked once per tick from the package's source files), so a release never runs beside reconcile logic still loaded from the old one.
- Typed gateway errors: Claude Code's session transcript (found through the client's sessions directory and read incrementally from its tail) classifies an error before the pane does, so `429 parallel cap` (the key's `max_parallel_requests`), `429 model TPM (model)`, `524 origin timeout`, `530 tunnel down` and `conn lost` are told apart even when the pane shows only the resend marker. Errors are stored with kind, subtype, label and an excerpt whose API keys, key hashes and email addresses are redacted (host store schema version 4, additive). A parallel cap lowers the pool's working cap host-wide for a cooldown (`[gateway] parallel_cap_step`, `parallel_cap_minutes`) instead of feeding the breaker.
- `theseus top`, second round: GATEWAY lists recent errors with project, agent, task, typed error, attempt, outcome or next retry and pool state, and opens a detail popup; AGENTS shows `CPU (core %)`, `MEM (RAM)` and a `context` meter (profile field `context_limit`); the CPU figure is the mean of every thread with the busiest one and the CPU history has a time axis; popups have titled sections, dim keys and colored values, one-row buttons, and close on a click outside; the pane mirror scrolls sideways and has a type-through mode.
- Supervised agents (`theseus.supervisor`): with `[agents] managed = true` and `[agents.counts]` (usually in `theseus.local.toml`; `[defaults] agents.counts` in the host config) theseus starts each long-running agent in a hidden pane of its own private tmux server (`tmux -L theseus`, `[supervisor]` in the host config), records every run in the host store (`agent_runs`, schema version 5, additive) and reconciles in `theseus agents up` and every queue tick: missing agents start, crashed ones restart after a backoff (a pane-died hook records the exit and the last screen at once) until `failed`, changed launch configuration is reported as `drift`, removed slots stop once free. Agents holding a task resume their conversation after a crash, reboot or lost server; the others start fresh. A thrashing agent, or one whose conversation is gone, restarts fresh and gets its task's restart prompt. Startup dialogs are never answered (`blocked`). New commands: `theseus agents up|down|ls|restart|attach|logs|migrate`; `migrate` moves an agent from a hand-made pane onto the private server under the same name, resuming its conversation. New states `starting`, `blocked`, `failed` and `waiting` (from `claude agents --json`). The pane runs `theseus agents _exec`, which applies the profile environment in-process, so no secret appears in a pane command, scrollback or log. Profile fields `interactive.exit`, `session_flag`, `status_command`, `ready_pattern`, `startup_dialogs`, `paste_placeholder`.
- A snapshot API for the dashboard (`supervisor.snapshot`, `capture`, `send`, `attach_argv`, `open_window`); the existing agent popup mirrors and sends to supervised agents, and Open tmux pane opens them in a new window of your own tmux.
- `theseus queue wait` and `queue run` sleep until the next interval or the earliest pending wake time (a scheduled gateway resend, the end of an agent's restart backoff), so retries fire on time instead of at the next interval boundary.
- `theseus instance restart|compact` accept an agent name as well as a pane.
- `theseus top` polish: no table row is highlighted until asked (Escape or a click elsewhere clears it); Enter or a double-click opens details for a waiting task, an event or an agent, and the agent popup mirrors its tmux pane live with a send line (verified send), Enter, Escape, Interrupt and Compact buttons and Open tmux pane; `theseus top --back` returns a tmux client to the dashboard after a jump; EVENTS sort by any column; `?` or F1 opens a help popup generated from the key bindings; colors follow the Textual theme with readable contrast and distinct activity colors (delivered, partial and blocked now each have one, none of them the error color) and stay distinct on 16-color terminals; agent memory bars show the share of system RAM; the layout fits the window without scrolling the whole screen; one compact line per GPU; tables update in place and GPU queries are cached for 2 seconds.
- Gateway error recovery for persistent instances: an idle pane showing a gateway error of its profile (`interactive.gateway_patterns`) is in state `gateway_error`; retryable errors (429, 5xx) are resent after `max(retry_after, backoff)` with `gateway_error` and `resent` events, a fresh context (`/clear` and a restart prompt) from the second error of a task or above `gateway.clear_tokens`, and a `stalled` event after `gateway.attempts`; fatal errors record an `error` event and are never resent. Retry state lives in the host store (schema version 3, additive). A host-wide circuit breaker (`[gateway]` in the host config) pauses assignments and resends on a gateway pool (`gateway_paused`), and `theseus top` shows gateway health per pool.
- Verified send: every message the queue types is checked for submission (busy marker, one more Enter for a stuck input line, `send_failed` otherwise), and `theseus instance send AGENT (TEXT | --file PATH)` exposes it to coordinators.
- `THESEUS_DB_GUARD`: a path the host store refuses to open; the test suite isolates the host store, host configuration and XDG roots for the whole run and fences off the real database with it.
- `theseus top` is now an interactive Textual dashboard over every project on the host: a Host tab (projects, pools, merged events) and one tab per project (agents, waiting tasks, events, activity sparklines), with `/` filtering, `p` to pause or resume a queue, `r` to refresh and Enter on an agent to switch your tmux client to its pane. It runs outside any project too.
- Host registry filled by every command that loads a project configuration, and `theseus projects` to list it.
- `theseus top --host --once` and `--host --json` for a plain host summary, and `theseus top --interval SECONDS`.
- Host store (`theseus.store`): one SQLite database per machine (`~/.local/share/theseus/theseus.db`, `THESEUS_DB` overrides) is now the runtime source of truth for queue events, pool leases and claims, the agent registry, the project registry, deliveries and agent-state samples written by every queue tick. Task records stay in `tasks.json`.
- One-time migration: the first command in a project imports its `agents.json` and `queue/events.jsonl`, and the first on the host imports the pool state files and `projects.json`; the old files are left in place.
- `theseus db check|maintain|backup|restore FILE --yes|prune`: integrity and size report, retention trim with `ANALYZE`, optimize, incremental vacuum and WAL truncation, online backups with an integrity check and 7 daily plus 4 weekly rotation, restore that saves the current database first, and explicit removal of projects whose root is gone. The queue runs maintenance and a backup at most once a day. Retention and backups are configured in `[store]` of the host `config.toml`.
- `theseus doctor` shows the host store (path, schema version, size, last backup, last maintenance) and project names claimed by two roots.
- `theseus top` dashboard look: boxed, titled sections in the plain dashboard's state colors; a stable accent color per project (tab label, section borders, host tables); project cards on the Host tab; one stacked activity bar chart per project tab (series per kind group, legend, time axis) and one for all projects on the Host tab; CPU, load, memory, swap and GPU meters with an in-memory CPU history and per-core view (`c`); CPU and memory bars per agent.
- Thrashing is a stall: an agent holding a task whose pane shows one of its profile's `interactive.stall_patterns` (Claude Code presets: "Autocompact is thrashing") is reported in state `thrashing` at once, busy or not, and the queue records one `stalled` event, which wakes `theseus queue wait`, and never nudges it.
- `interactive.env` for a profile: it and the profile's `env` are put in front of the persistent instance's launch and restart as `env VAR=value ...`, for example `CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS = "10000"` to make agents read large files in ranges.
- Per-task profiles: `theseus tasks add ... --profile NAME` and `theseus tasks profile ID [NAME]`. The queue gives such a task only to agents registered with that profile, or relaunches an agent whose profile differs only in MCP servers or environment onto it first (a `relaunched` event) and back onto its registered profile before its next task that does not need it. The dashboard says `needs profile NAME` when no agent can take it.
- docs/agent-profiles.md: an example REA variant (`[workers.gateway-rea]`) used only for tasks that need REA's session state, with everything else on a lean profile.
- `theseus instance restart` launches the agent fresh with the same name and permission mode when the session to resume no longer exists (`interactive.resume_missing`), and reports it.
- Host configuration, `~/.config/theseus/config.toml` (`XDG_CONFIG_HOME` is respected, `THESEUS_CONFIG` overrides the path), for everything specific to one user or machine: host-wide agent profiles (`[workers.<name>]`), pools (`[pools.<name>]`), host store retention and backups (`[store]`), tool locations (`[tools.paths]`) and defaults for project keys a project leaves unset (`[defaults]`, such as `workers.default`). Layers, lowest to highest: package defaults and presets, host, project `theseus.toml`, project `theseus.local.toml`, `THESEUS_*` variables and command line flags. A project section named like a host profile overrides only the keys it sets (`env` and `interactive` merge key by key), so `[workers.gateway] capacity = 4` inherits the rest from the host.
- Profile field `extra_args`: arguments appended to the headless run, the resume and the persistent-instance launch after the MCP flags, with placeholders filled and a leading `~` expanded, for example a client settings file.
- `theseus config show --sources` prints every resolved value, including each configured profile's fields and the host pools and store settings, with the layer it came from (package, host, project, project-local, env).
- `theseus config check` validates the host file too, also outside a project: an unknown section, profile key, pool key or store key is an error naming the file and key; an unknown `[defaults]` key is a warning. Unknown keys in a project's profile sections are reported as warnings.
- `theseus setup host` writes a commented starter host file (refuses to replace one without `--force`; `--print` prints it); `--import-project PATH [--dry-run]` moves a project's `[workers.*]` tables and its `theseus.local.toml` `[tools.paths]` into the host file and prints the project lines that can then be removed, without editing the project.
- `theseus tools set --host NAME PATH` records a tool location in the host file. Tools now resolve from the environment, then `theseus.local.toml`, `theseus.toml` and the host file (`[tools.paths]` in each), then `PATH` and install locations; a configured location that does not work falls through to the next.
- `theseus doctor` shows the host configuration file and its validation result.


### Changed

- An offline agent (stopped or scaled away) shows grey in the console instead of red, and no longer counts as trouble or an issue line; stalled, blocked, failed and waiting agents stay red.
- Task priority is a fixed scale from 1 (last) to 5 (first), default 3; `tasks add`, `tasks edit` and `tasks priority` refuse other values, and older records are read onto the scale (none or 0 as 3, the rest clamped). A ready task gains one level per `[queue] aging_hours` it has waited (default 24, 0 turns it off), up to 5.
- The queue plans each tick's free agents together: the strongest choose first and take the tasks only they can do, a stronger agent leaves easier tasks to free weaker agents unless there are more such tasks than weaker agents, and an agent that left its tasks to others takes whatever they did not. Equal effective priorities go to the task that has waited longest.
- The console's WAITING list has a priority column (`P3`, `P2+1` with aging) and shows a task's minimum capability as pips (`≥●●`, `any` without one, red when no agent meets it); AGENTS shows each agent's capability the same way. `theseus tasks ls` prints the priority and minimum capability, and `theseus agents ls` the capability.
- Task commands no longer commit anything: an assignment is a store write plus the task message, so new tasks no longer wait for a commit or push, and `merge`, `unmerge` and the queue stop writing `chore:` record commits. Workers read their record from the store (`theseus tasks show ID` works in a worktree). `theseus check` validates the store from the project's own checkout and the committed export elsewhere.
- `theseus tasks list --all` lists in store order: archived tasks first, then open ones.
- The task message typed into an agent is a pointer: `theseus task show ID` for the record (`theseus tasks show ID` for a hand-made pane) and how to report, instead of the record text.
- Owned paths overlapping a running task's now hold a task until that one is merged (they were only a warning).
- `theseus tasks priority`, `profile` and `capability` are aliases of `tasks edit --force`: they still work on in-progress tasks (leaving the worker an edit note) and are refused on delivered or merged ones.
- Only `tasks assign`, `rebase`, `unmerge`, `reopen`, `retire` and `import` wait for a running queue tick; other task commands no longer do.
- A claim refuses a task outside the current milestone, past its profile's capacity or held, unless forced; a forced claim records a `forced` event, and abandoning it restores what it superseded.
- Cap cuts are sticky: after a key-level 429 the reduced cap holds for `[gateway] parallel_cap_minutes` after the latest such error, then rises one slot every `cap_step_up_minutes` (10) instead of jumping back to the full cap.
- `theseus tasks rebase ID` also brings a worktree with uncommitted edits up to the base ref: it stashes the edits (untracked files included), moves HEAD and replays them, recording the new base only when they replay cleanly. Conflicts stay in the worktree as conflict markers with a copy of the edits kept in the stash, and merge refuses until the worker resolved them. A worktree whose HEAD moved without its files gets main's changes merged into those files in place.
- The agent popup keeps four buttons on one row: Attach (Enter, supervised agents), Type (i), Interrupt (asks first) and Close. Sending Enter or Escape (`E`), compact (`K`, `theseus instance compact`), open in your tmux (`o`) and restart, stop, start (`R`, `X`, `U`) are keys and Ctrl+P commands of the popup, listed in `?`.
- The Conversation tab reads like a conversation: assistant text renders as Markdown, each tool call is one `Tool: key argument` line (`Read: src/camera.c`, `Bash: theseus build`) that unfolds to its input as `key: value` lines, each result a one-line preview that unfolds; system reminders, command output, background task notices and compaction summaries are left out and slash commands show as typed. Transcript adapters supply this through two optional entry fields, `format` and `summary`; the console renders them for any adapter.
- AGENTS shows each agent's profile capability (`cap`) and WAITING each task's minimum capability (`min`, blank when unset, yellow when it is what keeps the task waiting); both are narrow and the first columns to drop out on a narrow console.
- The context meter and the gateway classification read transcripts through the profile's transcript adapter (`theseus.transcripts` moved to `theseus.adapters.claude_code`), so profiles of other CLIs fall back to the pane instead of being read as Claude Code transcripts.
- An unknown top-level section in the host `config.toml` or a project's `theseus.toml` or `theseus.local.toml` is ignored with a warning on stderr, printed once per process, instead of stopping the command, so a long-running `theseus queue wait` or `queue run` survives a newer release adding a section; `theseus config check` still reports it as an error.
- The console's AGENTS table has no pane column (every agent is private); the agent popup lists the pane.
- `theseus agents restart NAME --fresh` refuses an agent that holds a task unless `--with-task`.
- A many-agent queue tick no longer waits on each verified send in turn: silent agents cost one verification window per tick.
- Screens theseus saves (`crash-GEN.txt`) are redacted like the gateway excerpts: API keys, key hashes, `sk-` tokens and email addresses.
- `theseus db prune` also removes a gone project's gateway errors, retry episodes and pool slots.
- A profile without `interactive.exit` is stopped with a signal and skipped by `theseus agents migrate`, instead of being sent `/exit`; `theseus instance restart` takes its launch, resume and exit commands from the profile; the agent popup's Compact button runs `theseus instance compact` (the profile's compact command) instead of typing `/compact`.
- Console tables keep stable column widths that follow the window (fixed short columns, proportional flexible ones, optional columns dropping out when narrow); a cut cell ends in an ellipsis and never scrolls sideways. Panels and popups carry short labels only (no legends, hints or source prose); explanations live in the `?` help.
- `theseus config check` warns when `theseus.toml` lists `[instances] panes`: pane ids belong in `theseus.local.toml`.
- tmux is now required (supervised agents run on it). Every tmux call goes through one module (`theseus.tmux`) that always names the private socket for supervised agents; hand-made panes on your own server are driven exactly as before.
- The verified send treats Claude Code's `[Pasted text #N]` placeholder as text still in the input line, and for supervised agents clears a wrapped input line completely (one `C-u` clears one visual line).
- The Claude Code presets launch persistent instances as `{command} --name {agent} --permission-mode {permission_mode}`, and resume with the same line plus `--resume`, so a restarted agent keeps its name and permissions. `profiles.instance_env()` takes the agent name; without one, `instance restart` fills `{agent}` from the session record.
- The worker instance brief asks for short shell output and for findings to go into the report as the work goes, so they survive context compaction.
- Textual (`textual>=8.2,<9`) is now a runtime dependency. `theseus top --once` and `--json` keep their output; the old ANSI refresh loop is retired.
- The queue tick takes pool slots atomically (`store.acquire()`) and gives a slot back when the assignment fails, so concurrent queues never push a pool past its `max`.
- Event records returned by `workqueue.events()` (and in `theseus top --json`) also carry `id`, `project` and `epoch`.
- An unknown section in `theseus.toml` or `theseus.local.toml` is reported with the file that has it.

### Deprecated

- `theseus tasks archive` (now an alias of `tasks export`) and `theseus tasks migrate-ids` (agent ids live on the attempts in the store); `--no-commit` on `instance assign` and `dispatch` has no effect.
- `~/.config/theseus/pools.toml` and `~/.config/theseus/store.toml`: still read, below `config.toml` (which wins on each conflicting key), with a one-line note in `theseus doctor` and `theseus config check`. Move their tables into `[pools.<name>]` and `[store]` of `config.toml`.
- `<data>/queue/events.jsonl` is still appended as a plain-text audit trail but no longer read; it will stop being written in a later release. `<data>/agents.json`, the pool state files under `~/.local/share/theseus/pools/` and `~/.local/share/theseus/projects.json` are no longer written after their one-time import.

### Fixed

- `theseus tasks edit --touches` on a task whose patches were already observed (after a delivery, or by the tick's patch scan of a reopened task) failed with a UNIQUE constraint error; declaring a path now turns its observed row into the declaration.
- Automatic sends (task messages, nudges, restart and start prompts, `instance send`) no longer clear an input line that holds text theseus did not type: whoever is writing there keeps their draft, and the send is retried later as not typed. An unsent line theseus typed itself is still replaced.
- A send whose text left the input line counts as delivered even when the busy marker was never seen (a fast answer, as with OpenCode), so `instance send` no longer reports a false failure that invites a duplicate resend.
- The worker skill names the project's configured citation index (`[re] citation_index`) instead of the default path.
- `theseus agents remove`, `enable` and `disable` act on every name given (they acted on the first and ignored the rest), and report each name that failed; `theseus agents list --json` prints JSON like `ls --json`, which now also carries each agent's capability.
- A supervised queue driver restarts cleanly when the installed code changes: it runs as `python -c <boot line> queue run`, and the restart re-ran `python -c queue run`, which exited 1, so every release counted as a driver crash against its restart budget.
- The coordinator's start prompt is typed at most once per conversation: a send that typed the prompt but saw no busy marker (a fast answer, as with OpenCode) used to stay owed, and every queue tick typed the whole prompt again.
- An attached terminal now resizes a session's window on the private server as the terminal resizes: the attach hook ran `resize-window -A`, which sized the window once and left it at a manual size; it now sets `window-size latest` until detach pins the agent size again.
- The coordinator's mirror in the console sizes the coordinator's window to the mirror, as an agent's mirror does.
- The host config's `[models.context]` table now reaches projects (it was validated but never merged), so context meters use the configured window instead of the 200000 fallback.
- While a project's coordinator runs as the supervised session, the task message no longer tells workers to send their done line to the `[instances] coordinator` session name, which could reach a different session that once held that name; the store delivery and the attention push reach the coordinator.
- `theseus tasks ls` shows a held task as `held`, not `ready`.
- A worktree name truncated from a long task id no longer ends in a hyphen or dot (a trailing hyphen next to the path separator is suspected of confusing a client's permission path matching).

- A task whose dependency is merged now waits until that merge commit is in the assignment base (`[git] base`, normally `origin/main`; local `HEAD` for in-place assignment) before the queue tick, `theseus instance assign` or `theseus dispatch` assigns it, so its worktree no longer starts without the dependency's change while the merge is still local and unpushed. `theseus tasks list`, `theseus queue status` and the console show the reason (`waiting for A's merge 2ab13fb to reach origin/main`), and the queue records one `held` event, which does not wake `queue wait`. A dependency completed without a merge commit, or whose recorded commit no longer resolves, counts as satisfied as before.

- `theseus queue run` and `queue wait` read the project and host configuration again when one of its files changes, and reconcile retires an agent only when the current files no longer configure it, so an older watcher no longer stops an agent that `theseus agents scale` just added.
- An assignment whose task record is committed locally but not at a remote `[git] base` says to push it (`git push origin HEAD:main`) or to set `base = "HEAD"`.
- Reassigning a task to the agent (or `dispatch` name) that held it before no longer fails with `worktree already exists`: when the path is a git worktree a previous attempt of the same task left there, the assignment moves it and its `work/<name>` branch aside to `<path>-attemptN` and `work/<name>-attemptN` and records both on that attempt; any other existing path is still refused. `theseus tasks release` and `tasks unmerge` say where the worktree stays and where the next assignment moves it. A task whose queue assignment fails gets one `error` event and is skipped for `queue.assign_backoff_seconds` (300) while the queue keeps assigning other work, instead of failing again, and waking `queue wait`, on every tick.
- `theseus agents down NAME` no longer races the queue: it marks the agent down under the queue lock before stopping its pane (restoring the mark when the stop is refused), and the queue assigns nothing to an agent marked down. A task message that cannot be typed (the pane is gone) rolls the assignment back: the task is released with the reason, its worktree and branch are removed when they hold no changes, the record is committed and an `error` event names it, instead of leaving the task in progress on a stopped agent.
- `theseus agents down --force` on a busy agent stops it within seconds (SIGTERM, then SIGKILL) instead of waiting up to three minutes for it to go idle.
- `theseus merge` no longer reverts main when a worker moved its worktree HEAD onto newer main without its files (for example a hard reset to main followed by copying its edited files back): files whose worktree copy does not hold what main changed since the recorded base are merged three-way against that base with `git merge-file`, and a conflict stops the merge before main is touched. A conflicting delivery now names each file, the commits main gained since the worktree base (short SHA and subject) and the conflicting hunks, and says to have the worker rebase.
- Commits theseus makes on the coordinator's behalf (queue, assign, release, merge, unmerge and their record updates) commit only their own paths through a temporary index and leave everything else the coordinator staged staged; record commits no longer sweep a staged `tasks-archive.jsonl` in under an assign message. `theseus tasks archive` now commits `tasks.json` and `tasks-archive.jsonl` itself, so no record commit leaves archived tasks out of both files.
- Drift now covers everything that changes how a supervised agent launches: command, arguments, the model and the env built from it, env and interactive env values, MCP server definitions, extra_args, working directory and `launch_shell`. A host profile's model change was missed before, because only env names were hashed. `theseus agents ls` and the `drift` event name what changed (env variables by name, never by value), from a launch description kept per run in `<data>/agents/NAME/launch.json`; runs started by an older theseus are compared by their launch hash and need one manual restart before a model or env value change shows. `theseus agents restart --drifted` says `no drifted agents without a task` and exits 0 when there is nothing to restart, lists the drifted agents it skips because they hold a task, and says what each restart applied; it refuses NAMEs alongside `--drifted`, and a restart whose profile no longer resolves fails before the agent is stopped.
- `theseus agents` argument checks: `restart`, `attach` and `logs` name an unknown agent instead of printing the usage line, `remove`, `enable` and `disable` without NAME print usage, `down` and `migrate` refuse NAME together with `--all`, `up --all-projects` reconciles the other projects when one has configuration errors (and exits 1), and a profile error is reported instead of a traceback.
- Commands that change the queue (`theseus tasks` actions that write `tasks.json`, `merge`, `dispatch`, `instance assign`) take the project's queue lock, so a running queue tick and a CLI command no longer overwrite each other's task records or race in the main checkout; a command that has to wait says so. `tasks.json`, the queue's agent state and heartbeat files are replaced whole, so the console and a tick never read a half-written file.
- `theseus merge` commits delivered files whose names git quotes (non-ASCII characters) and files with spaces in their path: patch paths are read with `git apply --numstat -z` and worktree changes with `git status -z`, where they were parsed from quoted diff headers and missed.
- A queue assignment whose task message raises instead of failing (a vanished pane, a profile error) is rolled back like a failed send, instead of leaving the task in progress on an agent that never got it; an assignment that fails after its worktree was created removes the worktree and branch whatever the error.
- A graceful `agents down` or `restart` refused because the agent stayed busy no longer marks its run as stopped on purpose, which made a later crash of that run count as a planned stop (not restarted after `down`, restarted without a crash budget after `restart`).
- The pane-died hook reconciles an agent that used up its restart budget under the queue lock, like every other reconcile.
- `git fetch` of a remote `[git] base` fails after 120 s and never waits for a credential prompt, so an unattended queue tick cannot hang holding the queue lock; `theseus tasks retire` reports a failed worktree removal as an error instead of a traceback.
- `theseus tasks reopen` and `tasks unmerge` move the delivered `handoff.md` aside to `handoff.attemptN.md` (recorded on the attempt), so the next queue tick no longer takes the old handoff for a new delivery and bounces the task straight back; when the task's agent has meanwhile taken another task, both release the task to pending for the next free agent instead of leaving that agent with two tasks in progress.
- An agent at a permission prompt or startup dialog is `waiting` whether theseus supervises it or not: the pane's last lines are matched against the profile's new `interactive.prompt_patterns` (Claude Code presets: the `1. Yes` choice line of a permission prompt; other presets set none) and `interactive.startup_dialogs`. Hand-made panes never reported `waiting` before, so an idle-looking pane at a prompt got the queue's nudge (text plus Enter, which can approve the prompt). Nothing is typed into a pane that shows one: verified sends (task messages, nudges, restart prompts, resends), the queue's compact and clear, `theseus instance send|restart|compact` and a supervised agent's graceful exit all refuse or fall back to stopping the process; the console's send line, typed by a human, may answer it.
- New projects keep their data under `$XDG_DATA_HOME/<project>` (`~/.local/share/<project>` when it is unset): the scaffolded `theseus.toml` and the host template honor `XDG_DATA_HOME`. Existing projects keep the data root their `theseus.toml` names.
- A tmux call that gets no answer within its timeout raises `TmuxError`, which reconcile and the commands report, instead of an uncaught `TimeoutExpired`.

- Flaky supervisor tests: tmux 3.4 can miss the SIGCHLD of a pane's process (seen on one Linux host, not on CI), so `pane-died` fires only once another SIGCHLD reaches the server; the tests now signal SIGCHLD to their private server while they wait.
- A hand-made pane that no longer exists now shows as `offline`: tmux 3.4 exits 0 with empty output for `display-message` on a missing pane, which counted as alive.
- Busy markers are looked for in the last three non-blank screen lines, so a pane with empty rows below its output is still seen working.
